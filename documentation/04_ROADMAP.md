## 4.2. Ближайшие улучшения (Backlog)
1. **Мобильный Anti-DPI (если полевой тест покажет остаточные проблемы с QUIC/TLS на отдельных операторах)**:
   - Отказ от жёсткой зависимости на единственный пресет внутри группы или быстрый пресет-переключатель для мобильной сети (TTL 3–6 vs `disorder` / `oob`).
   - Проверка и при необходимости выборочная UDP-блокировка порта `443` строго для IP/портов QUIC YouTube/Meta (в дополнение к подавлению DNS Type 65).
   - Поддержка пользовательских/экспериментальных тестов в `StrategyTester` (например, проверка загрузки реального фрагмента превью `i.ytimg.com` или фрагмента манифеста видео).
2. **Улучшение SmartHosts**:
   - Автоматическая проверка отклика (health-check) европейских SNI-прокси IP в `scripts/update_domains.py`, чтобы исключать «умершие» релеи при генерации файла.
   - Отображение в настройках приложения даты актуальности базы из `domains_version.json`.
3. **UI / UX**:
   - Возможность остановить идущий автоподбор прямо кнопкой «Остановить» внутри уведомления в шторке (Notification Action).
   - Быстрый экспорт лога «Сетевого доктора» (NetworkDiagnostics) для отладки у разных сотовых операторов.

## 4.3. Архитектурные инварианты (не нарушать при развитии)
- Не пропускать российские сервисы, банки, `4pda.*` и `apis.google.com` через SNI-релеи или десинхронизацию.
- Не добавлять `com.google.android.gms` в автовыборку приложений.
- Не смешивать домены Anti-DPI и SmartHosts.
- Не удалять предыдущие релизы и теги на GitHub.
