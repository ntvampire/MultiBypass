# 1. Техническое задание (ТЗ) — MultiBypass

## 1.1. Назначение
**MultiBypass** — автономная Android-утилита раздельной маршрутизации (*Split-Tunneling*), десинхронизации TCP/TLS и локального обхода геоблокировок без использования удалённых коммерческих VPN-серверов. Весь трафик обрабатывается локально на устройстве.

## 1.2. Целевая платформа и ограничения
- **ОС**: Android 9.0+ (`minSdk = 28`, `targetSdk = 34`, `compileSdk = 34`).
- **Архитектуры (ABI)**: `arm64-v8a`, `armeabi-v7a`, `universal`.
- **Права и режимы**: работа без root-доступа через системный `VpnService` и локальные `ForegroundService` (`specialUse`).

## 1.3. Четыре контура маршрутизации (принцип разделения)
Система обязана строго разграничивать потоки трафика:

1. **Контур Anti-DPI (ТСПУ / замедления в РФ)**:
   - Сервисы: YouTube, Googlevideo, Discord, Instagram, Facebook/Threads, Twitter/X, Signal.
   - Обработка: TCP-десинхронизация через локальный движок `ciadpi` (`ByeByeDPI`) с поддержкой раздельных групп профилей (отдельная мягкая нарезка для Meta/Instagram и агрессивная с фейк-пакетами для YouTube/Discord).
   - DNS: принудительное разрешение через чистые публичные DNS (`8.8.8.8`, `1.1.1.1`, `9.9.9.9`, `77.88.8.8`) и подавление записей `TYPE_HTTPS` (`Type 65`) для мгновенного отката HTTP/3 (QUIC) на TCP TLS 1.3.

2. **Контур Geoblock (зарубежные ограничения по IP РФ)**:
   - Сервисы: OpenAI/ChatGPT, Anthropic/Claude, Google AI/Gemini, Perplexity, Canva, Spotify, Notion, JetBrains, Adobe, игры Supercell и др.
   - Обработка: локальный DNS-перехват (`SmartHosts`) на основе `smart-no-crutch.hosts` — мгновенная подмена A-записи (`0 мс`) на проверенные европейские SNI-релеи, а также подавление `Type 65` для таких доменов.

3. **Контур Telegram (sTGWS Proxy)**:
   - Автономный MTProto WebSocket-прокси (`127.0.0.1:1443`) с инкапсуляцией трафика в WebSocket поверх TLS через CDN Cloudflare.
   - Работает независимо от основного VPN-туннеля, минуя TUN-интерфейс (приложение Telegram не требует добавления в VPN).

4. **Прямой контур (Direct / Оператор связи)**:
   - Все российские сервисы (`.ru`, `.su`, `.by`, `.рф`), банковские клиенты, Госуслуги, маркетплейсы, `4pda.*`, `apis.google.com`, `suggestqueries.google.com`, а также все приложения вне списка `routedApps`.
   - Запросы идут напрямую через сеть оператора (`protect()`), сохраняя полную совместимость с операторскими «белыми списками» и тарификацией.
   - Локальные сети (`192.168.0.0/16`, `172.16.0.0/12`, `224.0.0.0/4`) исключаются из VPN-маршрута (`Bypass LAN & Multicast`).

## 1.4. Функциональные требования к UX и эксплуатации
- **Раздельный туннель по умолчанию**: при чистой установке `routeAllApps = false` — автоматически выбираются только установленные рекомендуемые приложения (`GEOBLOCK_PACKAGES` и `ANTIDPI_PACKAGES`), без `com.google.android.gms` (защита работы IoT/умного дома).
- **Автоподбор стратегий**:
  - Многоцелевой бенчмарк (`YT`, `YTV`, `IG`) через DoH и SOCKS5-контур.
  - Работа в фоне с `PARTIAL_WAKE_LOCK` и прогресс-уведомлением в шторке; клик по уведомлению открывает экран идущего автоподбора.
  - Автоматический расчёт раздельной связки (`YouTube/Discord` + `Instagram`) и сохранение результатов.
- **Устойчивость к смене сети**: бесшовный хэндовер Wi-Fi ↔ LTE со сбросом зависших сокетов и обновлением DNS оператора.
- **Обновления**:
  - Независимое обновление списков правил и стратегий из GitHub Pages (`ntvampire.github.io/MultiBypass`) с резервированием на GitHub Raw и локальные assets.
  - Встроенный механизм обновления APK через GitHub Releases API и стандартный системный установщик (`FileProvider` + `ACTION_VIEW`).
