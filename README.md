## 🌟 Основные функциональные модули

- **Группа 1: Модуль избирательного DNS (DNS Privacy & Resolution)**:
  - Поддержка классического UDP-резолвинга и защищённого шифрованного протокола **DNS-over-HTTPS (DoH, RFC 8484)**.
  - Встроенные конфигурации публичных доверенных DNS-сервисов: **Google Public DNS, Quad9, AdGuard DNS, Comss.one, Yandex DNS, NextDNS** (с возможностью привязки пользовательского ID профиля), а также произвольный ввод DoH URL / IP-адресов.
  - Локальный DoH-шлюз на loopback-интерфейсе для защиты DNS-запросов от подмены (DNS Spoofing / Poisoning) и несанкционированной модификации промежуточными узлами.
  - Настраиваемый белый список доменных имён и пакетов приложений, требующих изолированного разрешения.

- **Группа 2: Модуль десинхронизации пакетов (TCP Desynchronization / DPI-тестирование)**:
  - Встроенный нативный C-движок `ciadpi` для исследования устойчивости TCP-сессий методами сегментации потока данных (fake SNI, split, disorder, out-of-band data, модификация TTL).
  - База типовых конфигурационных профилей для лабораторного анализа задержек и стабильности потока.
  - **Автоматический замер метрик (Benchmark / Автоподбор)**: циклическое тестирование стратегий десинхронизации с измерением сетевой задержки (RTT, latency ms) и процента успешной доставки данных к тестовым узлам.
  - Гранулярная фильтрация целевых доменов и приложений для обработки через туннель десинхронизации.

- **Локальный транспортный шлюз Telegram WebSocket (MTProto WS)**:
  - Автономный локальный фоновый сервис на Rust (`127.0.0.1:1443`), инкапсулирующий трафик в защищённый WebSocket/TLS-транспорт.
  - Управление жизненным циклом сервиса в один клик.
  - Автоматическая генерация криптографически стойкого сессионного ключа (`SecureRandom`) и удобная интеграция с клиентом Telegram через `tg://proxy`.

- **⚡ Изоляция на уровне ядра Android (Strict Split-Tunneling)**:
  - Приложения и сетевые адреса, не входящие в выбранные группы, направляются через физический сетевой интерфейс устройства напрямую в обход туннеля (`addAllowedApplication`).
  - Обеспечивает полную совместимость с банковскими сервисами, корпоративными сетями и ресурсами из локальных белых списков.

- **Встроенная система проверки версий**:
  - Автономная проверка наличия обновлений через публичный интерфейс релизов GitHub с автоматическим определением архитектуры процессора устройства (ARM64 / ARMv7 / Universal).

- **Интерфейс пользователя**:
  - Разработано на базе **Jetpack Compose** и **Material Design 3** с адаптивной тёмной темой и нативным системным пикером установленных приложений.

## 📥 Загрузка (Сборки APK)

Готовые скомпилированные и подписанные пакеты размещаются в разделе релизов репозитория:
👉 **[Перейти к релизам MultiBypass на GitHub](https://github.com/ntvampire/MultiBypass/releases/latest)**

- **`MultiBypass-v<версия>-arm64-v8a.apk`** — 64-битная архитектура ARM (рекомендуется для подавляющего большинства современных устройств на Android 9+).
- **`MultiBypass-v<версия>-universal.apk`** — универсальный пакет, содержащий бинарные библиотеки для всех архитектур.
- **`MultiBypass-v<версия>-armeabi-v7a.apk`** — 32-битная архитектура ARM для более ранних моделей устройств.

## 🛠️ Сборка из исходного кода

Проект собирается стандартными средствами Android SDK и NDK:
- **Java / JDK**: версия 17 (Temurin или OpenJDK).
- **Android NDK**: версия `r26d`.
- **CMake**: версия `3.22.1+`.
- **Система сборки**: Gradle 8.x.

Автоматическая компиляция и формирование релизов выполняются в защищённом окружении **GitHub Actions** (конфигурации в папке `.github/workflows/`).

## 💖 Благодарности и сторонние компоненты (Credits & Attribution)

Проект **MultiBypass** разработан с использованием открытого программного кода и наработок следующих независимых проектов:

- **[ByeByeDPI (ciadpi)](https://github.com/hufrea/byedpi)** (автор: [@hufrea](https://github.com/hufrea))  
  Низкоуровневая реализация сетевой утилиты на C для управления фрагментацией TCP-пакетов, манипуляций с заголовками TLS ClientHello и генерации OOB-данных. Компилируется в библиотеку `libbyedpi.so`.

- **[hev-socks5-tunnel](https://github.com/heiher/hev-socks5-tunnel)** (автор: [@heiher](https://github.com/heiher))  
  Высокопроизводительный сетевой шлюз интерфейса TUN в протокол SOCKS5, транслирующий трафик виртуального сетевого адаптера Android (`VpnService`). Компилируется в `libhev-socks5-tunnel.so`.

- **[ByeDPIAndroid](https://github.com/romanvht/ByeDPIAndroid)** (автор: [@romanvht](https://github.com/romanvht))  
  Архитектурные решения по связыванию `hev-socks5-tunnel` и `ciadpi` в Android через JNI-прослойку.

- **[tgws / Telegram WS Proxy](https://github.com/coyove/tgws)** (и реализация MTProto WebSocket на Rust)  
  Сетевой транспорт для WebSocket-инкапсуляции трафика MTProto. Скомпилирован в библиотеку `libtgwsproxy.so`.

- **[OkHttp & okhttp-dnsoverhttps](https://github.com/square/okhttp)** (Square)  
  Библиотека сетевого взаимодействия для реализации DNS-over-HTTPS (RFC 8484).

- **[Jetpack Compose](https://developer.android.com/jetpack/compose)** (Google)  
  Декларативный UI-фреймворк для Android.
